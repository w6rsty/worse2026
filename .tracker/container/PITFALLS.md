## Known up-front (design-time)
- **FixedArray must store `usize mSize`, never a `T* mpEnd` into its own buffer** — a
  self-pointer dangles after a `memcpy` trivial-relocation move, silently corrupting the
  moved-to object. (DECISIONS R7.)
- **C++20 module scan order is dependency-driven, not file order** — a cycle in the import
  DAG fails the build cryptically. Keep the DAG acyclic (see plan §DAG). `memory_util`
  imports `type_traits`+`utility`+`allocator_traits`; nothing imports back up.
- **Open-addressing hash invalidates ALL refs/iterators on rehash/erase** — document on
  every mutating method; never hand out long-lived element pointers. (DECISIONS D2.)
- **No exceptions anywhere** — `-fno-exceptions` is a target. No `throw`, no
  `std::vector`-style strong-guarantee that relies on catch. Use `WE_ASSERT`/`WE_VERIFY` +
  abort + sentinel/`Optional` returns.
- **Route ALL allocation/lifetime through `AllocatorTraits`** — never raw `new`/
  `construct_at`/`destroy_at` in a container; the traits layer honors member
  construct/destroy + source_location threading and is the only sanctioned path.

- 2026-06-01 — Repo has a pre-commit clang-format hook: it auto-reformats C++ files and FAILS the first commit; must re-stage the reformatted files and commit again. track.sh done may need a second attempt, or pre-format first.
- 2026-06-01 — utility ADL clash: in-house move/forward/swap live in worse::core and collide with std::move/forward/swap. An UNQUALIFIED call (e.g. forward<T>(x)) whose argument is a std type pulls std's overload in via ADL -> 'call is ambiguous'. Fix: fully-qualify every internal call as worse::core::move/forward/swap (qualification suppresses ADL). Applies to all future container/algorithm code operating on generic T.
- 2026-06-01 — IteratorTraits primary template must be EMPTY for non-iterators. A primary that writes 'using ValueType = typename It::ValueType;' hard-errors (NOT SFINAE) when IteratorTraits<int> is merely NAMED inside a requires-expression, because instantiating the class instantiates every member alias. Fix: empty primary + VoidT<nested types...>-detected partial specialization (std::iterator_traits does the same). Reuse this idiom for any trait that reads nested typedefs.
- 2026-06-01 — __builtin_memcpy / memcpy on a trivially-RELOCATABLE-but-not-trivially-copyable type triggers clang -Wnontrivial-memcall (e.g. relocate<Reloc> where Reloc has a user move ctor+dtor but is opted into IsTriviallyRelocatable). This is the INTENDED use of the relocation fast path. Silence by casting args: __builtin_memcpy(static_cast<void*>(dst), static_cast<void const*>(src), n*sizeof(T)). Recurs in every container grow/rehash that memcpy-relocates.
- 2026-06-01 — GTest macro + templated type comma: EXPECT_DEATH({ FixedArray<int,2> a; ... }, "") fails — the preprocessor splits on the comma in FixedArray<int,2>, giving 'too many arguments'/'use of undeclared identifier'. Fix: alias the type before the macro (using FA2 = FixedArray<int,2>;) and use the alias inside. Applies to any EXPECT_*/ASSERT_* wrapping a multi-arg template.
- 2026-06-01 — Release-only macro bug (found via bench): WE_ASSERT_MSG's NDEBUG branch was defined with ONE param (cond) while usage + the non-NDEBUG branch take TWO (cond,msg). Debug never defines NDEBUG so it was dormant; the FIRST release/NDEBUG build of array.cppm failed with 'too many arguments to macro'. Fix: WE_ASSERT_MSG(cond, msg) in both branches. Lesson: compile the lib under a release preset periodically — debug-only builds hide NDEBUG-gated breakage.
- 2026-06-01 — Flat-container overload trap: a templated by-key erase(K const&) BEATS erase(ConstIterator) when passed a NON-const Iterator (Pair*), because the template is an exact match while erase(ConstIterator=Pair const*) needs a qualification conversion. Symptom: 'comparison between pointer and integer' deep inside the comparator. Fix: constrain the key overload requires(!IsSame<RemoveCvRef<K>,Iterator> && !IsSame<RemoveCvRef<K>,ConstIterator>). FlatSet was immune only because its Iterator==ConstIterator (non-template then wins). Recurs in any container pairing a templated key method with an iterator overload.
- 2026-06-01 — murmur3 fmix64(0) == 0 is a FIXED POINT (0 -> 0 through all the xor-shift/multiply steps). A hash-finalizer avalanche test must NOT assert hashFinalize(0) != 0; test non-zero inputs scatter + stay distinct instead. Same holds for any multiply-xorshift mixer.
- 2026-06-01 — Open-addressing info/DIB byte width: a u8 displacement byte (max 254) silently corrupts under a DEGENERATE hash (all keys colliding -> displacement grows with element count, not table size; growing the table does NOT help a constant hash). Use u16 so heavy-collision workloads stay correct; growth alone cannot bound displacement when the hash maps everything to one bucket. Applies to any Robin Hood / linear-probe table tested with a constant BadHash.
- 2026-06-01 — Node list (list/forward_list): construct/destroy ONLY the `&node->mValue` subobject, NEVER the whole `ListNode`. Allocate raw bytes (sizeof(Node), alignof(Node)), set the base link pointer(s) by hand, then AllocTraits::construct(&node->mValue, args...); symmetric AllocTraits::destroy(&node->mValue) then deallocate(node, sizeof(Node), alignof(Node)). Constructing the whole node would default the base + need a node ctor taking the value's args.
- 2026-06-01 — Node list move/swap reseat asymmetry: the doubly-linked `list` is CIRCULAR (boundary nodes point at the embedded `mAnchor`), so move/swap MUST reseat those boundary links onto the new anchor (reuse intrusive_list's reseat + spliceAll). The singly-linked `forward_list` is NULL-TERMINATED — nothing points back at `mBeforeBegin` — so it must NOT reseat; only the head pointer + size transfer. Don't "helpfully" add a reseat to forward_list.
- 2026-06-01 — Node list sort/merge/reverse must NOT touch `mSize` (count is invariant under reorder); only splice/spliceAfter change counts (cross-list, per R26). Corollary: `sort` empties the ring into stack bins while `mSize` stays at the original value, so its internal loops MUST test the ring pointer (`mAnchor.mpNext != anchorPtr()` / `cur != nullptr`), NOT `empty()`/`size()` which would lie mid-sort.
- 2026-06-01 — Move-assign with a non-propagating + non-equal allocator must element-wise MOVE values into freshly-allocated nodes (then let the source free its own), never steal nodes: a node allocated by allocator A must be freed by an allocator == A. Steal path is only valid when propagate OR allocators compare equal. (Default Allocator is always-equal -> always the cheap O(1) steal.)
- 2026-06-01 — `unique`/`unique(pred)` does NOT advance the retained anchor on a removal: after dropping a duplicate it compares the SAME kept element against the next survivor (matches std/EASTL). So {5,6,7} with pred (b-a==1) -> {5,7} (one removed, not a cascade). Easy to mis-assert in tests.
- 2026-06-01 — Fixed inline node pool (fixed_list/fixed_slist): MOVE and SWAP MUST be element-wise, NEVER a pointer-steal — the nodes live in the object's inline buffer, so moving the object relocates the storage and any stolen node pointers/links would dangle (the inline analogue of R7 / the IntrusiveList reseat trap). Consequence: iterators/pointers into a fixed list ARE invalidated by move/swap (unlike heap List). Free-list is threaded through each slot's own `mpNext`.
- 2026-06-01 — Fixed-list test pacing: within a push/pop cycle the live count must never exceed N or the hard-cap WE_ASSERT fires (correctly). A loop doing two pushes against one pop net-grows past capacity and aborts — pop first (or balance push/pop) to exercise free-list recycling at full capacity.
- 2026-06-01 — Cross-pool node ops are impossible on fixed lists: `splice` (transfer node identity with no element moves) cannot hold between two distinct inline pools, so it is omitted; `merge` is implemented element-wise (move values into this pool, capacity-checked). Not std-crippling — a physical constraint of inline storage.

Identity-hash experiment left Robin Hood unchanged (7.3k→7.2k map, 6.3k→6.3k set) while EASTL stays ~3.2k. We already beat std::unordered_set (6.3k vs 9.7k); only EASTL's cache-warm chained nodes pipeline ~2x better. hash_cache as queued will NOT move the int bench.
